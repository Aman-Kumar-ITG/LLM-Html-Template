Deep Dive — Sampling

The server borrows the client’s brain.

A tool running on the server can call create_message() to make the connected client generate text — then use the result inside its own workflow.

1Initiate

On the server, inside a tool call, run create_message() with the messages you want the model to see.

2Callback

On the client, implement a sampling callback that receives those server-supplied messages.

3Message format

MCP messages are converted to your SDK’s format — e.g. small glue logic for the Anthropic SDK.

4Return result

After generation, return a CreateMessageResult containing the generated text.

5Connect

Pass the sampling callback into the ClientSession so the server can reach it.

6Consume

Back on the server: use the text in a workflow, sample again, or return it.

server.py 
@mcp.tool()
async def summarize(ctx: Context, text: str):
    prompt = f"Summarize:\n{text}"
    result = await ctx.session.create_message(
        messages=[SamplingMessage(
            role="user",
            content=TextContent(
                type="text", text=prompt))],
        max_tokens=4000,
        system_prompt="You are a research assistant.")
    return result.content.text
Choosing a Transport

Two ways to move a message.

stdio

Standard I/O

Client and server share a local process boundary, exchanging JSON over stdin/stdout. Simple, fast, ideal for desktop and local tooling.

  • + Zero network setup
  • + Lowest latency, local
  • – Single client, no scale-out
streamable http

StreamableHTTP

Server-Sent Events stream server→client messages over HTTP, with sessions and resumability. Stateless mode unlocks load-balanced horizontal scaling.

  • + Remote & multi-client
  • + Scales behind a load balancer
  • – Flags gate server-initiated reqs
The Decision Rule

Local tool, one user → stdio.  Remote service that must scale → stateless StreamableHTTP.  Need server-initiated calls → mind the state flags.
